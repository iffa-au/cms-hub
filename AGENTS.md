# cms-hub — IFFA backend + admin CMS

Two apps in one repo:

| | | |
|---|---|---|
| `backend/` | Express + Mongoose, TypeScript | App Runner |
| `client/` | Next.js 16 admin CMS | Amplify |

The public site is a **sibling repo**: `../iffa-2026`. It consumes this API
read-only except for the submit-film form. Check `../iffa-2026/AGENTS.md`
when a change affects what the public site renders.

**Read `docs/STATUS.md` before starting work.** This file holds only things
that rarely change.

## Running it

```bash
cd backend && npm run dev     # tsx watch, port 8000
cd client  && npm run dev
```

The local backend reads the **production MongoDB** via `MONGO_URI`. Treat every
write as a production write. It has no AWS credentials, so any S3 upload fails
locally with `CredentialsProviderError` — that's expected, not a bug.

## The Mongoose trap

**A field declared only in the TypeScript interface is silently dropped.**
Mongoose `strict` mode saves nothing that isn't in the actual `Schema` object.
The interface will typecheck, the write will succeed, and the field will not
exist in the database.

This has bitten this project before (`submission_year`). When adding a field to
`submission.model.ts`, add it in **both** places and verify with a real query,
not by reading the code.

## API shape

`GET /api/v1/submissions?year=YYYY` — public, **approved-only**, sorted
`{ createdAt: -1, _id: -1 }`. The `_id` tiebreaker is load-bearing: the 267
records for 2022–2025 were bulk-imported outside Mongoose and have no
`createdAt` at all.

`?featured=true` (or `isFeatured=true`) switches to the admin-curated carousel
set — sorted by `featuredOrder`, limited to 5, **not year-scoped**.

The projection maps `crew.directors` → `crewDirectors`. The legacy `directors`
array comes from a separate crew-linking workflow most submissions never go
through, so it is usually empty. Keep both; the frontend prefers `crewDirectors`.

`contactEmail` is PII: it appears in the staff list projection and is stripped
from the public single-submission route via `.select("-contactEmail")`. Don't
add it to a public projection.

## S3 / CloudFront

The media bucket sits behind `dhbdzeb2cbayq.cloudfront.net`. Uploads are
presigned PUTs issued by `libs/s3.ts` — the browser never gets credentials.

Submission assets go in one folder per submission:

```
iffa/images/submissions-2026/<title-slug>-<8hex>/
  banners/portrait.webp
  banners/landscape.webp
  crews/director-sam-raimi-1.webp
```

The `<8hex>` ref is generated by the browser and shared by every upload in one
form session. It exists because **titles are neither unique nor stable** — two
"Dust" submissions would otherwise overwrite each other's posters, silently,
since S3 PUT overwrites without error.

`assetPrefix` on the submission is **recomputed server-side** from the ref and
title. Never accept a path from the client: that string is what a prefix-delete
would walk.

Partner logos live in a separate `partners/` prefix and allow PNG; the public
submit form stays webp-only.

Two config gotchas, both previously hit:

- S3 CORS `AllowedOrigins` must have **no trailing slash** — browsers never send
  one, so `https://example.com/` never matches.
- CloudFront preflight needs `OPTIONS` in the behavior's allowed methods. This
  is separate from S3's CORS config and is currently missing on the CloudFront distribution.

## Environment

`backend/env.example` lists the full set. Uploads additionally need
`AWS_S3_BUCKET` and `CLOUDFRONT_URL` — missing either throws `S3ConfigError`
with the variable named, deliberately rather than falling back to a wrong URL.

Never create `.env.backup*` files. They are not covered by `.gitignore` and will
be committed with real secrets by a `git add .`.

## Before claiming something works

Verify against the running system, not the source. Curl the endpoint, query
MongoDB directly, check the actual S3 key. Several bugs here read correctly and
were wrong in production — and a "verification" against the wrong endpoint
(public vs staff projection) is worse than none.

Deploys are manual: **backend changes do nothing until App Runner redeploys.**
